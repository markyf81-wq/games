# Fateless Kingdoms

## Purpose and runtime

A standalone, browser-local card game for one human versus a CPU. Open `index.html` in Chrome directly, or serve the parent games repository with a static server. No installation, build, CDN, account, paid AI or network API is needed. Use ordinary deferred scripts, not modules or fetched JSON, to preserve direct-file support.

## Files

- `index.html`: table, scoreboard, hand, inspector, portrait toolbar/information sheet and native dialogs.
- `styles.css`: isolated dark green/gold presentation, desktop table fitting, narrow-screen layouts and reduced motion.
- `cards.js`: all 62 printed cards, names, base powers, ability text and local artwork paths.
- `engine.js`: state transitions, legal target prompts, scoring, protection, CPU action enumeration and save validation.
- `cpu.js`: three search budgets; sampled unknown hands, forward simulation and card-conservation evaluation. It is sampled lookahead, not full MCTS or a trained model. See `AI_NOTES.md`.
- `cpu-worker.js`: optional background search when served over HTTP. Direct-file mode uses a yielding main-thread fallback.
- `game.js`: DOM rendering, choices, dialogs, lobby/coin flip, turn scheduling, worker fallback and persistence.
- `effects.js`: detached card flights, destruction burns and event cues; cancel overlays on a new match and respect reduced motion.
- `audio.js`: local orchestral recording and result-cue playback, generated sound effects, user gesture activation and separately saved audio settings.
- `assets/music/`: three full compressed Scott Buckley tracks plus three short result excerpts under CC BY 4.0; retain attribution and the excerpt edit notices in `CREDITS.md` and Settings. These are third-party assets, not original game music.
- `assets/effects/`: eight illustrated animated SVG row scenes for weather, War Chant, Dread, Ironward, Sanctuary and Shielded. Each SVG respects reduced motion internally; CSS adds them behind cards and suppresses the older line-pattern pseudo-elements.
- `assets/cards/`: 62 compact progressive JPEG exports of Mark's PSDs. Originals remain in `~/Downloads/3-version3/` and must not be overwritten.
- `RULES.md`: local rules snapshot with card-text corrections and Mark’s clarifications. Keep How to play self-contained, without a link to Mark’s Google Doc.

## Rules and invariants

- Printed artwork always wins over conflicting text. Preserve extra rulings only where print leaves a detail open.
- The default shared deck contains exactly one of each of 62 cards, with 15 starting cards each. Custom games filter entire Omen/Spell types from the pool and choose a starting hand size, optionally guaranteeing exactly three combined Spell/Omen cards per player; use `engine.cardPool` and the saved match options for conservation and CPU hidden-card sampling. Older saves without options use the full default pool; missing `guaranteedStart` means false. Keep the optional boolean backward-compatible in save validation and normalize it through `engine.matchOptions`. Guaranteed deals split the shuffled pool into units and specials, deal three specials and the remaining units to each hand without replacement, shuffle each hand, and recombine/shuffle leftovers into the shared deck. Do not fill guaranteed hands from the combined pool or introduce duplicate cards. Maintain unique card IDs and conservation across deck, hands, fields, weather and destroyed piles.
- Mechanical Men, Assassin and The Spy all have Infiltration.
- Printed Accuracy includes Target itself. Printed Shielded includes Stone Wall itself. Printed Sacrifice destroys one friendly unit and returns up to two destroyed units to hand; Mark’s clarification excludes the unit sacrificed in that same play. Build recovery choices only from the pre-play destroyed pile. It never deploys a replacement or triggers returned units.
- Every nonempty selection step must ask for an explicit choice, including when only one option exists or every available option must be selected. This applies to row placement, Restoration, Death Gaze, Convert, Decoy, both Sacrifice steps and Weakest Link's cutoff selection. Skip only empty target sets; deterministic effects with no selection step still resolve automatically. Sacrifice asks which unit to destroy before asking which units to recover. CPU action enumeration must supply the same explicit selections; keep the main-page and worker engine cache versions aligned.
- Combat/Ranged/Siege row types are enforced. Dread blocks new cards entering its row, including both directions of a Convert swap. Convert movement does not replay abilities.
- Spell immunity includes friendly Spells. Shielded prevents destruction, not Decoy returning a unit. Resolve destruction protection simultaneously before removing any Omens. Round cleanup clears protected cards too.
- Weather sets affected unit power to 1; War Chant then adds 2. Ironward blocks both harmful and beneficial Omens. Dynamic abilities recalculate from the field.
- Pridefall and Weakest Link ignore protected units. Pridefall removes all eligible highest ties; Weakest Link removes at most three per side with selectable cutoff ties. Death Gaze and Convert choose one tied target.
- Spells go to the bottom of the shared deck after resolution. Row cards belong to their current field; middle weather goes to its original player's destroyed pile.
- Passing ends that player's participation for the round. Automatically pass either player only when their hand is empty, after fully resolving draw/recovery effects and when starting a round. Nonempty hands never trigger an automatic pass merely because every card is blocked or lacks useful targets; manual/CPU strategic passing is still allowed. `settleEmptyHands` applies this in normal engine transitions and CPU sampled simulations; `autoPassEmptyHands` immutably normalizes restored real states from the UI before turn scheduling. Never apply it directly to a redacted public view with unknown hands represented by empty arrays. Log automatic passes and resolve normally when both players have passed. Both pass to resolve. Ties award both a win; both reaching two draws the match. Starter alternates. No between-round draw.
- Round-end fields remain visible for review until Continue in the result modal. This presentation pause allows no further moves before cleanup.
- The CPU must receive `engine.publicView`, not the real opposing hand or deck order. Publicly recovered cards are tracked in `knownHands`; that is legitimate observed knowledge.
- Chronicle messages must not identify cards drawn or recovered into the CPU hand. CPU gain animations use card backs.
- Both the outer layout and inner table grid must constrain their columns with `minmax(0,1fr)` so the hand cannot push the battlefield under the sidebar. The sidebar stacks below the table at 980px.
- UI and CPU must use the same `prompt`/`play` engine. CPU enumeration caps alternatives for performance; human choice prompts retain every legal target.

## Persistence and audio

`fateless-kingdoms.match.v1` stores `{ state, level }` in localStorage. Next-game preferences use `fateless-kingdoms.settings.v1` with `{ options: { handSize, includeOmens, includeSpells, guaranteedStart }, level }`. Each new match snapshots its own `state.options`; changing preferences cannot change an active match’s pool. State version 1 uses rules fingerprint `printed-v1`. It includes players' hands/rows/graves/wins/pass flags, shared deck, middle weather with owners, public known-hand cards, starter, round, phase, results and bounded history. Validate before restoring; blocked storage falls back to in-memory play. Old saves without optional `knownHands` start tracking future revealed cards. `fateless-kingdoms.audio.v1` separately stores `{ music, effects, musicVolume, effectsVolume, muted }`; music and effects default on and master `muted` defaults false. Master mute pauses music/result cues, silences the effects gain and prevents new effects without changing the per-channel preferences or playback positions. The muted flag persists across reloads; older saves without it default false. Unmuting resumes the current scene according to the individual toggles. The battle-score update enables music once for existing audio saves using `musicRevision: 2`; subsequent mute choices persist. Music uses local native Audio elements so playback works over HTTP and directly from disk, without remote requests or fetch/decode restrictions. Begin game or the first gesture after restore activates audio; blocked autoplay waits for a later gesture. `audio.setScene` selects a two-track battle playlist (Balefire, 5:40; Legionnaire 2022 Remaster, 3:07) during play, Chronicle (4:15) in the lobby, or a separate results scene. Pause the main soundtrack immediately at `roundEnd`/`gameOver`, preserving its exact position. Once the result dialog is ready after animations, `audio.playResult` plays one non-looping victory/defeat/draw excerpt at music volume; the outcome matches the modal (overall match result at game over). Leave results silent after the cue ends. Reopening the same result must not replay the cue. Restored results may wait for the first gesture before playing; hiding pauses any cue and visibility resumes its remaining portion. Continue resumes the battle playlist where it paused and interrupts any remaining result cue. Reset/Play again calls `audio.resetMusic` to stop cues and rewind both full playlists to their first tracks, returning to lobby music. Preserve mute/volume preferences. Use the recordings and excerpts, not oscillator-based result music; result tunes follow Music settings independently of Sound effects. Create players lazily with `preload=none`; do not preload all music on page load. Pause immediately when hidden/pagehide and resume when visible after activation. Handle rejected play promises and skip failed files without retry loops. Sound effects retain their separate Web Audio compressor/gain path. Keep musicRevision 2 so this update preserves existing mute/volume choices. Settings includes expandable music credits with track, composer and CC BY 4.0 links; retain the music sources and re-encoding notice in `assets/music/CREDITS.md`. `game.js` blocks further plays until the reveal and transition finish. Compute and save the legal next state before the reveal so refresh during an animation preserves a committed move. Keep it in `pendingState` until the reveal ends; all other saves must prefer that pending state. Apply it to the displayed board after the reveal and guard both stages with the presentation token so Reset game cannot resurrect a cancelled play. Save again on pagehide for an active match; never save the undealt lobby preview after reset. Keep `vh` fallbacks before `dvh` for older Chrome; old OS/browser compatibility has not been verified on actual legacy hardware.
