# Fateless Kingdoms

## Purpose and runtime

A standalone, browser-local card game for one human versus a CPU. Open `index.html` in Chrome directly, or serve the parent games repository with a static server. No installation, build, CDN, account, paid AI or network API is needed. Use ordinary deferred scripts, not modules or fetched JSON, to preserve direct-file support.

## Files

- `index.html`: table, scoreboard, hand, inspector, portrait toolbar/information sheet and native dialogs.
- `styles.css`: isolated dark green/gold presentation, desktop table fitting, narrow-screen layouts and reduced motion.
- `storage.js`: nonthrowing JSON persistence using the existing match/settings/audio keys; loaded before audio and game bootstrap.
- `card-preview.js`: `CardPreviewController` owns hover/focus/touch previews, gesture state, listener cleanup and release-click suppression.
- `cpu-controller.js`: `CPUController` owns delayed searches, worker/fallback lifecycle, cancellation and single job completion.
- `table-layout.js`: `TableLayout` owns synchronous card/sidebar measurements, batched resize observation and observer cleanup.
- `ARCHITECTURE.md`: runtime boundaries, class ownership, play flow and maintenance guidance.
- `REVIEW.md`: review findings, cleanup scope and verification status.
- `cards.js`: all 62 printed cards, names, base powers, ability text and local artwork paths.
- `engine.js`: state transitions, legal target prompts, scoring, protection, CPU action enumeration and save validation.
- `cpu.js`: a reactive Kids policy plus three search budgets; sampled unknown hands, forward simulation and card-conservation evaluation. It is sampled lookahead, not full MCTS or a trained model. See `AI_NOTES.md`.
- `cpu-worker.js`: optional background search when served over HTTP. Direct-file mode uses a yielding main-thread fallback.
- `game.js`: match orchestration, DOM rendering, choices, dialogs and lobby/coin flip; delegates persistence, preview/layout and CPU job lifecycles to their dedicated services/controllers.
- `effects.js`: detached card flights, destruction burns and event cues; cancel overlays on a new match and respect reduced motion.
- `audio.js`: sampled battle effects, Web Audio decoding/voice limits, user gesture activation and separately saved audio settings; delegates music to MusicPlayer.
- `music-player.js`: MusicPlayer owns native media voices, playlist overlap, phase crossfades, result cues and cancellation.
- `sound-effects.js`: selected Sonniss-licensed and CC0 MP3 excerpts embedded as base64 for direct-file-safe Web Audio decoding.
- `assets/sounds/CREDITS.md`: source recordings, selected filenames, processing and separate Sonniss/CC0 licence details.
- `assets/music/`: three full compressed Scott Buckley tracks plus three short result excerpts under CC BY 4.0; retain attribution and the excerpt edit notices in `CREDITS.md` and Settings. These are third-party assets, not original game music.
- `assets/effects/`: eight illustrated animated SVG row scenes for weather, War Chant, Dread, Ironward, Sanctuary and Shielded. Each SVG respects reduced motion internally; CSS adds them behind cards and suppresses the older line-pattern pseudo-elements.
- `assets/cards/`: 62 compact progressive JPEG exports of Mark's PSDs. Originals remain in `~/Downloads/3-version3/` and must not be overwritten.
- `RULES.md`: local rules snapshot with card-text corrections and Mark’s clarifications. Keep How to play concise and limited to game rules, without interface controls, storage/audio/settings descriptions or a link to Mark’s Google Doc.

## Rules and invariants

- Printed artwork always wins over conflicting text. Preserve extra rulings only where print leaves a detail open.
- The default shared deck contains exactly one of each of 62 cards, with 15 starting cards each. URL-only debug mode is the documented asymmetric-deal exception; it still conserves one of each card. Custom games filter entire Omen/Spell types from the pool and choose a starting hand size, optionally guaranteeing exactly three combined Spell/Omen cards per player; use `engine.cardPool` and the saved match options for conservation and CPU hidden-card sampling. Older saves without options use the full default pool; missing `guaranteedStart` means false. Keep the optional boolean backward-compatible in save validation and normalize it through `engine.matchOptions`. Guaranteed deals split the shuffled pool into units and specials, deal three specials and the remaining units to each hand without replacement, shuffle each hand, and recombine/shuffle leftovers into the shared deck. Do not fill guaranteed hands from the combined pool or introduce duplicate cards. Maintain unique card IDs and conservation across deck, hands, fields, weather and destroyed piles.
- Mechanical Men, Assassin and The Spy all have Infiltration.
- Printed Accuracy includes Target itself. Printed Shielded includes Stone Wall itself. Mark’s explicit exception lets your own Sacrifice destroy Shielded units, including Stone Wall itself; Sanctuary still blocks Sacrifice. Pass the sacrifice effect context to the shared protection check in both prompt selection and destruction resolution. Other destructive cards, including your own Weakest Link and its tied-target choices, retain normal Shielded protection. Printed Sacrifice destroys one friendly unit and returns up to two destroyed units to hand; Mark’s clarification excludes the unit sacrificed in that same play. Build recovery choices only from the pre-play destroyed pile. It never deploys a replacement or triggers returned units.
- Every nonempty selection step must ask for an explicit choice, including when only one option exists or every available option must be selected. This applies to row placement, Restoration, Death Gaze, Convert, Decoy, both Sacrifice steps and Weakest Link's cutoff selection. An empty required target set blocks a core play such as Convert or a targeted Spell. Death Gaze and Restoration are when-played effects: skip only their empty target sets and still permit legal unit placement. Infiltration permits placement with zero cards to draw. Weakest Link shows all victims as explicit choices when there is no contested cutoff tie, including when every eligible unit must be destroyed. If a cutoff tie is contested, ask only for tied units and name the lower-power units that are also destroyed. Show the total friendly/enemy destruction counts in both the details and target steps. Weakest Link may skip an empty side if the other side has targets; deterministic effects with no selection step still resolve automatically. Sacrifice asks which unit to destroy before asking which units to recover. CPU action enumeration must supply the same explicit selections; keep the main-page and worker engine cache versions aligned.
- Mark’s refined legal-play ruling distinguishes core actions from when-played bonuses: ordinary units remain playable in a legal row when Death Gaze/Restoration has no eligible target or Infiltration has no cards to draw. Enforce this in `engine.prompt` so the UI, direct `play` validation and CPU action enumeration agree. Block targetless Convert and Decoy. `pickIfAvailable` skips empty Death Gaze/Restoration choices but still requires an explicit selection whenever any eligible target exists. Keep a concise no-target/no-draw note in the action summary so the player can decide whether to spend the unit’s ability now. Sacrifice must have both a friendly unit outside Sanctuary (ignoring Shielded) and at least one unit in the pre-play grave before offering its first choice. Infiltration draws up to two cards, including zero from an empty deck; its legal placement is independent of the draw. Pridefall, Weakest Link and Catastrophe need at least one eligible destruction target across both sides, checked with the same simultaneous protection rules used by resolution. Purge is explicitly playable with no Omens: it spends the turn, destroys nothing and returns to the bottom of the shared deck. Enforce this through the shared prompt/play/actions path for human and CPU. One eligible side is sufficient. Ordinary units, passive abilities and persistent row/weather Omens remain legal in an available location even before their bonuses/protections matter; Patience intentionally remains playable. Keep blocked cards inspectable and visually identical to playable hand cards: normal brightness and full opacity. Show a specific reason and no Play button in the modal. Do not auto-pass a nonempty blocked hand. Existing saves remain valid; this changes future move legality, not card conservation or the save schema.
- Combat/Ranged/Siege row types are enforced. Dread blocks only new unit cards entering its row, including both directions of a Convert swap; Omens always remain placeable. Ironward suppresses Dread’s restriction while both are present, and normal entry blocking resumes if Ironward is removed. Keep the Dread scene/blocked-row treatment suppressed under Ironward. Mark approved the revised Dread artwork saying “No new unit cards”; the original PSD stays untouched. Convert movement does not replay abilities.
- Spell immunity includes friendly Spells. Shielded prevents destruction, not Decoy returning a unit. Resolve destruction protection simultaneously before removing any Omens. Round cleanup clears protected cards too.
- Weather sets affected unit power to 1; War Chant then adds 2. Ironward blocks both harmful and beneficial Omens. Dynamic abilities recalculate from the field.
- Pridefall and Weakest Link ignore protected units. Pridefall removes all eligible highest ties; Weakest Link removes at most three per side with selectable cutoff ties. Death Gaze and Convert choose one tied target.
- Spells go to the bottom of the shared deck after resolution. Row cards belong to their current field; middle weather goes to its original player's destroyed pile.
- Passing ends that player's participation for the round. Automatically pass either player only when their hand is empty, after fully resolving draw/recovery effects and when starting a round. Nonempty hands never trigger an automatic pass merely because every card is blocked or lacks useful targets; manual/CPU strategic passing is still allowed. `settleEmptyHands` applies this in normal engine transitions and CPU sampled simulations; `autoPassEmptyHands` immutably normalizes restored real states from the UI before turn scheduling. Never apply it directly to a redacted public view with unknown hands represented by empty arrays. Log automatic passes and resolve normally when both players have passed. Both pass to resolve. Ties award both a win; both reaching two draws the match. Starter alternates. No between-round draw.
- Round-end fields remain visible for review until Continue in the result modal. This presentation pause allows no further moves before cleanup.
- `CPUController` accepts only `engine.publicView` input. It owns worker creation, a pending job identity, a single fallback and cancellation; do not rebuild those flags in `game.js`. Reset calls `cpu.cancel()`. Worker/fallback completion can fire only once per pending job.

## Debug mode

Append `?debug=1` to the game URL (works with direct-file URLs too). There is no debug setting or menu item. The URL flag is a convenience, not authentication. The page title and opening log identify debug matches.

`engine.debugHand()` selects all 14 Spells/Omens plus the 12 units with abilities, giving the human 26 unique cards. `matchOptions` snapshots optional `debug:true`, forces both special types on and disables the exact-three guarantee. `newMatch` removes those cards from the shuffled pool, then deals the CPU its configured hand size from the remaining ordinary units. Shared deck, rows, recovery, scoring and targeting rules remain normal. There are no copies, refill cheats, revealed opponent cards or immunity bypasses; cards without valid core actions stay blocked. CPU action generation/sampling uses the same conserved pool and rules engine.

Debug match persistence uses logical `debugMatch` / localStorage `fateless-kingdoms.match.debug.v1`; the ordinary match key is untouched, including on reset and pagehide. Removing the URL parameter returns to the normal saved game. Only the matching mode's saved state is restored. Old saves without `options.debug` stay normal. Keep all uniqueness/type/round validation active; validate debug's boolean and its forced inclusion/no-guarantee flags.

Debug settings show CPU starting cards, lock Spells/Omens on and the guarantee off. Saving debug settings preserves ordinary next-game card settings; CPU/audio preferences still apply normally. On restoring a debug match, its CPU hand-size option is retained. Regular matches and physical rules do not adopt this dealing mode.
