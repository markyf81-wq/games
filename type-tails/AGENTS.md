# Type & Tails — agent guide

Read the root `../AGENTS.md` as well. This guide describes this game's implementation; do not apply its mechanics to other games.

## Purpose and files

A cozy typing game set in a room with one of five freely selectable animal buddies. Players type practice words, complete rounds at WPM targets to unlock difficulties, and spend earned coins on pet outfits and room decorations.

- `index.html`: page layout, inline SVG room and pet, typing input, level menu, stats, shop/results/pause/help dialogs, and the library return link. Element IDs are the interface used by the JavaScript.
- `styles.css`: responsive game styling, room and pet animations, reduced-motion support, and library return link styling.
- `game.js`: one strict-mode IIFE containing game data, save loading, audio, timer/input logic, reactions, shop, and DOM event wiring.
- `README.txt`: player-facing instructions and unlock tiers.
- `../previews/type-tails.svg`: static library thumbnail derived from the default room SVG. Update it when the room's default art changes significantly.

Open `index.html` directly in Google Chrome, or enter from the library at `../index.html`. No build tools or downloads are required. Keep relative asset paths and conventional browser scripts.

## Mechanics and controls

- `LEVELS` defines eight difficulties. Unlock Explorer by completing Beginner at 12 WPM, Adventurer by completing Explorer at 18 WPM, Wordsmith by completing Adventurer at 22 WPM, Trailblazer by completing Wordsmith at 26 WPM, Expert by completing Trailblazer at 30 WPM, Master by completing Expert at 35 WPM, and Legend by completing Master at 40 WPM. The `unlockWpm` value belongs to the level being unlocked. Lifetime XP/coins never unlock further levels.
- Each difficulty combines two expanded focus groups (`lessons`) into a deduplicated `wordPool`. `PRACTICE_LETTERS` builds the cumulative allowed QWERTY letters; words containing unlearned letters are excluded. `selectRoundWords()` copies the pool, performs a Fisher–Yates shuffle, and takes exactly 20 distinct words. Every new round, including replay after an early exit, gets a fresh random selection and order. Never restore fixed word order or select from only one small focus group. Home-row keys come first, then E/R/U/I, T/O/P, Q/W/Y, C/V/B/N/M, Z/X, common TH/SH/CH/ST patterns, and everyday word endings. Pool sizes are currently 53, 118, 117, 123, 125, 108, 165, and 114 in level order. Every level must retain at least 20 eligible unique words. Keep the eight level indices stable for existing saves.
- `start-footnote` must exist in the HTML: `setPlaying()` updates it. A missing ID previously threw before `showWord()` and prevented the word/timer from starting. `showWord()` displays the first target and uses `focusTypingInput(true)` to focus/select the cleared input; round start repeats focus on the next animation frame to handle dialog focus restoration. Keep synchronous focus for mobile keyboards.
- Level selection happens before a round. Locked options display their thresholds. Any unlocked level can be replayed. Do not force players to play their highest tier.
- The per-word countdown is 14 seconds at Beginner and falls to 10 at Master/Legend. This is not a single timer for the whole round.
- `handleTyping()` compares the input case-insensitively to the displayed word. A match submits automatically; Enter is unnecessary. Backspace corrects mistakes. Paste/drop is blocked to keep speed rewards based on typing. Preserve composition handling for text input.
- Correct words earn the level's 40–100 base points, a speed bonus up to 80, and a streak bonus increasing by five per additional consecutive word up to 25. Timeout resets the streak and advances the round without a reward.
- Correct words credit lifetime XP and spendable coins immediately and save them. Spending coins must never decrease lifetime XP or relock levels. `bestWpmByLevel` is updated only after a completed 20-word round; early exits cannot unlock levels. `unlockedLevel` retains earned access permanently. Speed uses correct characters divided by five over active word time (including timed-out words, excluding pauses/transitions), rounded down so borderline results do not unlock early.
- Every correct word triggers a randomized funny pet action and bubble. `reactions`, `petReaction()`, and the `pet-*` CSS animations work together. Arm paths start at (0,0) inside inner `.arm-left`/`.arm-right` groups. Separate fixed wrappers translate these groups to (-32,33)/(32,33) in the pet's local coordinates. Wave/cheer rotate only the inner groups around `0 0` using `transform-box:view-box`. Never use room-coordinate pivots on these locally translated limbs: this previously sent the waving arm flying. Cheer uses mirrored left/right rotations.
- Choose pet opens `pet-dialog` between rounds. `PETS` defines Pip the cat, Biscuit the dog, Clover the rabbit, Maple the fox, and Mochi the panda. All five are free and available immediately; switching never costs coins or changes progress/inventory. The choice button is disabled during rounds. `applyPet()` replaces only ears, facial markings, tail, palette, and pet labels; accessories and their visibility persist. Picker portraits use the same ears/face/markings data. Shared body, face, paw, and shoulder anchors keep all shop outfits compatible with every animal.
- Escape/Pause opens the pause dialog; switching to another tab also pauses. Resume restores the remaining word time without charging paused time. Pausing during a word transition must continue with the next word on resume, without crediting a word twice or skipping one.
- Finishing early keeps already-earned points. Results show correct words, rewards, typing accuracy, streak, and WPM; WPM uses correct characters divided by five and active word time.

## State and browser saves

`SAVE_KEY` is `type-and-tails-v1`. Keep it stable or implement an explicit compatible migration.

Persisted fields: `xp`, `coins`, `owned` (item ID array), `equipped` (array of independently visible owned item IDs), `pet` (one of `cat`, `dog`, `rabbit`, `fox`, `panda`; missing/invalid values default to `cat`), `selected` (difficulty index), `rounds`, `lessonRounds` (eight nonnegative per-level completion counters; retained for save compatibility, not word ordering), `bestWpmByLevel` (eight completed-round speed records), `unlockedLevel` (highest permanently earned difficulty), `bestWpm`, `music`, and `sound`. Loaded values are validated. Older saves without `lessonRounds` initialize per-level completion counts to zero without changing XP, coins, or inventory. Do not use these counters to force a word order; all rounds draw a fresh shuffled sample. If `unlockedLevel` is absent, `LEGACY_POINT_TIERS` preserves difficulties already earned under the former point-based system once; subsequent unlocks use only completed-round WPM. Never use the legacy point tiers to grant new unlocks after migration. Legacy slot-to-ID equipment objects migrate to ID arrays: crown→medal, wizard→cape, beret→socks, wall-peach→curtains, and wall-blue→cloud-mobile. Ownership transfers one-for-one at unchanged prices; coins/progress are retained. Previously conflicting owned hats/rugs/walls are shown together during this one-time migration; non-conflicting items retain their visibility. New array saves preserve every individual show/hide choice. Initialization saves the migrated state immediately. Unknown items and unowned equipment are ignored. Storage failures must allow play and show the saving limitation.

Active-round state and animation/timer handles are transient. Reloading does not restore an in-progress round, but rewards already credited are saved. Do not replace or clear a player's stored progress during ordinary edits. Browser storage is scoped to the page origin; moving between hosts or local-file locations may expose different storage.

## Shop and decorations

`ITEMS` defines price, category (`pet`/`room`), and an independent item ID. There are no equipment slots or exclusivity rules. Every catalog item must be compatible with every other item. Buying adds the item to both ownership and the visible-ID array. Show/put-away toggles only that item's membership; never overwrite another item or hide it as a side effect. The shop is unavailable during a round.

Pet items: one party hat, shades, bow, royal medallion, starry cape, and socks. The cape sits behind Pip's body; socks cover the paws; the medallion sits below the bow; the hat and shades occupy different head areas. All accessories remain inside `pet`/`pet-motion` so funny actions animate them together. They are shared across all five animals, with no separate purchases or animal-specific equipment slots. Keep ears to either side of the hat and retain the shared face/paw coordinates. `HATS` contains only the party hat SVG. Future hats/accessories must have distinct, compatible positions rather than replace existing pieces.

Room items: plant, mountain print, lamp, bunting, yarn ball, wall sparkles, rose rug under Pip, smaller meadow mat by the side table, sunset curtains at the window, and a cloud mobile above the shelf. The wall itself keeps its default color; the former competing wall finishes were converted into curtains/mobile. Keep decoration positions compatible and preserve their SVG IDs.

`applyDecorations()` checks `state.equipped.includes(id)` independently. `paintRug()` and `RUG_STYLES` render the rose diamond rug and mint leaf mat. `cloneRug()` removes all IDs from copies. The meadow mat lives inside `side-rug`, scaled and translated away from the main rug; hiding either rug must not alter the other. `rugPreview()` uses the same painting helper for matching shop previews. Keep lifetime progress independent of balance, validate affordability, and save after transactions. Never revert the shop to mutually exclusive equipment slots.

## Audio and presentation

`MUSIC_SCORE` expands four eight-bar sections into two varied passes (64 bars, 512 steps). `MUSIC_TEMPO` uses 0.42-second steps in the room (about 3m 35s per cycle) and 0.34-second steps during a level (about 2m 54s). `MUSIC_PHRASES`, `MUSIC_HARMONIES`, and `MUSIC_SECTIONS` define melodies, voiced/arpeggiated chords, bass, rests, and quieter sections. Active rounds use a brighter, shorter triangle-wave melody, short bass pulses, and quiet synthesized kick/snare/hat percussion. A paused or finished round returns to the calm sine-wave room arrangement on the same running score, without restarting the loop. `setPlaying()`, pause, and resume synchronize audio state. Keep the arrangement varied and avoid reverting to a short repeating phrase. The `audio` object synthesizes background melody/chords and effects with Web Audio oscillator/envelope nodes. No audio assets or network requests are needed. Create/resume its AudioContext only after a real user gesture. Music and effects have separate gains and saved switches. Hide/mute scheduling follows page visibility. Disconnect completed notes, percussion sources, envelopes, and filters; reuse one noise buffer for percussion. Avoid adding duplicate music intervals when starting another round or toggling audio. Percussion routes through the music gain so the music toggle mutes it independently of sound effects.

`fitWord()` sizes long words to the typing card and runs on resize. Keep beginner words large, expert words readable, mobile input usable, and motion preferences respected. The library link must point to `../index.html`. The speech bubble is raised above Pip; during play on narrow screens it sits beside Pip to avoid both the cat and the typing card. `.room-card.is-playing` controls this responsive placement.

## Editing and verification

For tuning difficulty and vocabulary, edit `LEVELS` and keep its key progression aligned with `PRACTICE_LETTERS`; for outfits/decorations, edit `ITEMS`, `HATS`, and `applyDecorations()` together; for reactions, edit `reactions` and matching CSS keyframes; for animals, edit `PETS` and `applyPet()` while preserving existing animal IDs and accessory anchors. Update this guide and `README.txt` when mechanics or speed targets change.

Follow the root verification policy: source review is normal; do not automatically run browser checks or test tools. There is currently no automated test suite. If Mark requests a focused browser check, relevant scenarios are correct/incorrect/timeout input, pause/resume around the last word, unlocked/locked selection, shop affordability/equipping, independent audio switches, saved progress after reload, narrow-screen words, and the return link. Report only checks actually performed.
